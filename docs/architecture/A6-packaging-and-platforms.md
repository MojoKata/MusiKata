# A6. Packaging and platforms

A6.1. **One Python, one Qt, three platforms.** `packaging/versions.env` pins the Python (a
python-build-standalone build, by version and SHA-256 per platform), PySide6, Mutagen, NumPy, the
platform modules of A4.5, PyAV (A4.1), `truststore` and Chromaprint's `fpcalc` per platform (A7),
and every build tool. Each pin moves only to a release at least 14 days
old, as in AppKata, and only by a commit there.

A6.2. **PySide6 Essentials and Addons.** Qt Multimedia, whose `QAudioSink` and `QMediaDevices`
playback uses (A4), is in `PySide6-Addons`, which also carries large modules MusiKata doesn't use
(WebEngine, 3D, Charts, Graphs, Bluetooth and more). The builds install both, then remove the
modules not on an allow list in `packaging/qt-modules.txt` before packing, the way AppKata trims its
AppImage. A test starts the packed app and plays a file, so a module removed by mistake fails the
build. Qt Multimedia's FFmpeg plugin, which only `QMediaPlayer` needs, is left out: PyAV carries the
FFmpeg that decodes (A4.1).

A6.3. **Linux: AppImage.** Built on Ubuntu 22.04 for its glibc, as AppKata's is, with the same
appimagetool and runtime pins. It carries Python, Qt, PyAV and its FFmpeg libraries, and the xcb
libraries Qt needs; from the system it takes only what every desktop of R1.1 has (glibc, OpenGL,
PulseAudio or PipeWire's Pulse server, D-Bus, fonts). It installs itself into the app menu on first
start, with a `.desktop` file whose MIME types list the file kinds of R1.7 (so MusiKata is offered
in "Open with" and never set as the default), and, when asked (R1.9), updates itself from the
project's releases.

A6.4. **Windows: Inno Setup,** per user by default, built under Wine in a container as AppKata's
is, with PyInstaller freezing the app. It registers the file kinds of R1.7 for "Open with" only.

A6.5. **macOS: two app bundles, each in a `.dmg`** (R1.4), one for Apple silicon (arm64) and one for
Intel (x86_64), not one universal bundle: NumPy, PyAV and others publish a separate wheel per chip,
which a universal bundle would have to merge. Both are built with PyInstaller on an Apple silicon
macOS runner, the Intel one with the x86_64 Python and wheels under Rosetta, since GitHub's Intel
runners are going away. The window uses the system's title-bar buttons over a full-size content view
(R6.4), and the bundle declares the document kinds of R1.7 with the `Alternate` handler rank, so
macOS offers MusiKata without making it the default.

A6.5.1. **Signing.** The bundles are ad-hoc signed (`codesign --sign -`), which Apple silicon
requires of all code and which costs nothing; Gatekeeper still asks the user to allow the first
start (**Open Anyway**). The release steps keep a place for a Developer ID: once there is one, the
same bundles are signed with it, notarized and stapled, and MusiKata's cask moves from its own tap
to Homebrew's.

A6.5.2. **Homebrew.** MusiKata's own tap (`MojoKata/homebrew-musikata`) has one cask, `musikata`,
naming both `.dmg`s with their SHA-256 and choosing by the Mac's chip. A release updates it
(`build-and-release.md`).

A6.6. **Licenses.** Each build carries `LICENSE.txt` and `THIRD-PARTY-NOTICES.txt`: the licenses of
Python, Qt and PySide6 (LGPL-3.0), PyAV (BSD) and its FFmpeg (LGPL-2.1), Mutagen (GPL-2.0-or-later),
NumPy (BSD), Chromaprint's `fpcalc` (LGPL-2.1), `truststore` (MIT) and the platform modules,
generated by a script from the installed packages so it can't fall behind.

A6.7. **The demo library.** Tests, the tour and the screenshots never use real music. A script
generates a demo library: short tones and noise encoded to each kind of R2.2 with FFmpeg, tagged
with the made-up artists and albums of the mockups, some of them deliberately wrong (missing
years, lower-case artists, odd genres, missing covers) so Needs attention and R3 have work to
show.
